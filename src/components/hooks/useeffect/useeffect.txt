If you write:  useeffect Runs code after render

useEffect(() => {
  console.log("useEffect runs");
});

(with no dependency array)

It runs:

✅ After the first render.
✅ After every re-render.


    useEffect(() => {

        console.log("use effect runs")
        
    },[])  runs only for first render or f5 page render not state change render


    Easy rule
useEffect	When it runs
useEffect(() => {})	After every render (initial + every re-render)
useEffect(() => {}, [])	Only after the initial render
useEffect(() => {}, [count])	After the initial render and whenever count changes


useEffect is not for storing data.

It is used to perform side effects, such as:


Fetching data from an API
Starting a timer
Adding an event listener
Connecting to a WebSocket
Logging something after render and also for create timers, event listeners, subscriptions, or other resources.


const [count, setCount] = useState(0);
When the component unmounts, React automatically removes this state. You don't write:

return () => {
  // No cleanup needed for useState
};


Rule to remember
✅ useState → No cleanup needed.
✅ useEffect → Cleanup only if the effect creates something that should be stopped or removed


useEffect = Create / Start something

Cleanup = Stop / Remove that thing
